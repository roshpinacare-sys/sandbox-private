# INTEGRATION — חוזה ה-API של שרת-HQ (פורט 3010)

**למי מיועד:** סוכן הפורטל הראשי (Next.js על פורט 3000) — זהו החוזה המחייב לתקשורת מול שרת-HQ.
**מקור המימוש:** endpoints אלה ממומשים על-ידי סוכני 42-a/b/c ב-`sanbox/server.ts`. אם תשובה מהשרת חורגת מהחוזה — **החוזה (המסמך הזה) הוא האמת**, לא התשובה.
**גרסה:** 1 (Task 42-d)

---

## 1. עקרונות יסוד

1. **JSON בכל הכיוונים.** גוף-בקשה ותשובה: `Content-Type: application/json` (למעט תשובות-שגיאת-תחביר אפשריות של השרת — תמיד לתפוס `json` parse-fail).
2. **אין CORS.** השרת משרת את ממשק ה-fallback מאותו-מוצא בלבד. הפורטל מדבר עם השרת **מצד-השרת** (server-side proxy), לא מהדפדפן.
3. **אפס-URL-מוחלט בקוד-לקוח.** בדפדפן כל `fetch` הוא יחסי: `fetch('/api/...')` עם `credentials: 'same-origin'`. אסור `http://localhost:3010` או כל URL מוחלט אחר בקוד-לקוח.
4. **הסשן הוא הכול.** כל endpoint פרט ל-`POST /api/login` דורש כוקי-סשן תקף. אין פעולות אנונימיות.

---

## 2. חוזה הכוקי — `hq_session`

| תכונה | ערך |
|---|---|
| שם | `hq_session` |
| דגלים | **HttpOnly** (בלתי-נגיש ל-JS) — הרכב הדגלים המדויק לפי מימוש השרת; העיקרון: HttpOnly + `Path=/` |
| תוקף | **7 ימים** (`Max-Age=604800`) |
| נקבע | רק על-ידי `POST /api/login` בעת הצלחה |
| נמחק | על-ידי `POST /api/logout` |

כללים לסוכן הפורטל:

- **לא** קוראים, כותבים או מעבירים את הכוקי ביד — הוא HttpOnly ועובר אוטומטית ב-same-origin.
- בפרוקסי מצד-השרת (פורטל → 3010): מעבירים את כוקי הבקשה קדימה כמו-שהוא, ומחזירים את `Set-Cookie` של התשובה ללקוח ללא שינוי.
- **אסור** לשכפל את הסשן ל-localStorage/sessionStorage.

## 3. Endpoints

### 3.1 `POST /api/login` — כניסה

בקשה:

```http
POST /api/login HTTP/1.1
Content-Type: application/json

{ "password": "…" }
```

curl:

```bash
curl -i -c /tmp/hq.jar -H 'Content-Type: application/json' \
  -d '{"password":"…"}' http://localhost:3010/api/login
```

הצלחה — `200`:

```http
HTTP/1.1 200 OK
Set-Cookie: hq_session=…; HttpOnly; Path=/; Max-Age=604800

{ "ok": true }
```

כישלון — `401` (סיסמה שגויה) או `429` (הגבלת-קצב):

```json
{ "ok": false, "error": "…" }
```

(שדה `error` הוא מחרוזת-מידע; הלקוח מציג **הודעות-עברית משלו** ולא את תוכן השדה.)

### 3.2 `GET /api/status` — מצב מלא (דורש כוקי)

```bash
curl -b /tmp/hq.jar http://localhost:3010/api/status
```

הצלחה — `200`. דוגמה **ייצוגית** (המבנה מחייב, הערכים לדוגמה):

```json
{
  "ok": true,
  "uptime": 7342,
  "ports": { "p3000": 3000, "p3010": 3010 },
  "git": { "branch": "main", "trackedFiles": 118, "lastCommit": "a1b2c3d" },
  "vault": [
    { "name": "pat.env", "kind": "env", "masked": "github_pat_••••" }
  ],
  "scanLast": "2026-10-07T09:30:00.000Z",
  "sessionExpiresAt": "2026-10-14T09:30:00.000Z"
}
```

שדות:

| שדה | טיפוס | משמעות |
|---|---|---|
| `ok` | boolean | תמיד `true` בהצלחה |
| `uptime` | number (שניות) או string | זמן-פעילות השרת |
| `ports.p3000` / `ports.p3010` | number/boolean | הפורטים: הפורטל וה-HQ |
| `git.branch` | string | הענף הנוכחי |
| `git.trackedFiles` | number | מספר קבצים נעקבים |
| `git.lastCommit` | string | קומיט אחרון (hash ואולי תיאור) |
| `vault` | מערך | פריטי הכספת: `name` (שם), `kind` (סוג), `masked` (**ערך ממוסך בלבד**) |
| `scanLast` | חותמת-זמן | מועד סריקת-הסודות האחרונה |
| `sessionExpiresAt` | חותמת-זמן | מועד פקיעת הסשן |

כישלון — `401` (אין/פג סשן):

```json
{ "ok": false, "error": "…" }
```

### 3.3 `POST /api/action` — ביצוע פעולה (דורש כוקי)

בקשה — `action` הוא enum סגור:

```json
{ "action": "secret-scan" }
```

| ערך | משמעות |
|---|---|
| `secret-scan` | סריקת-סודות בקבצים הנעקבים — מדווח ממצאים, **לעולם לא תוכן הסוד** |
| `push-github` | דחיפת-גיט מאומתת דרך הכספת (הטוקן לא ב-argv, לא בקבצים) |
| `git-status` | סטטוס ענף/קבצים/קומיט |
| `ping` | בדיקת-חיות |

הצלחה — `200`:

```json
{ "ok": true, "…": "שדות-מידע נוספים לפי הפעולה — לתצוגה בלבד" }
```

הערך המובטח-המינימלי הוא `ok:true`; שדות נוספים הם מידע להצגה ואין להסתמך עליהם כחוזה-מכונה.
כישלון — `401` (סשן), `429` (עומס אפשרי), `4xx/5xx` אחר (פעולה נכשלה).

### 3.4 `POST /api/logout` — התנתקות (דורש כוקי)

```bash
curl -i -b /tmp/hq.jar -X POST http://localhost:3010/api/logout
```

הצלחה — `200`:

```json
{ "ok": true }
```

השרת מוחק את `hq_session`. אחרי זימון זה כל endpoint פרט יחזיר `401`.

## 4. קודי שגיאה והתנהגות נדרשת מהלקוח

| קוד | משמעות | מה הלקוח עושה |
|---|---|---|
| `200` | הצלחה | ממשיך כרגיל |
| `401` | אין סשן / סשן פג / סיסמה שגויה | **מסך-הכניסה** (`location.href = '/'`); אסור לופ של ניסיונות חוזרים |
| `429` | הגבלת-קצב/עומס | הודעה בעברית ("יותר מדי ניסיונות…"), בק-אוף — **אין לרספם** |
| `5xx` | שגיאת שרת | "שגיאה לא צפויה"; הפורטל שמפרוקסי יחזיר `502/503` משלו עם הודעה בעברית |
| חיבור נדחה / fetch-reject | **השרת אינו זמין** (לא רץ על 3010) | "השרת אינו זמין כרגע"; אין להסתיר זאת מהמפעיל |

חוזה ההפניות בין העמודים (ממומש בממשק ה-fallback — **השרת חייב לכבד אותו**):

- לוח המפעיל (`panel.html`) מפנה ל-`'/'` בכל `401`.
- שער הכניסה מפנה ל-`'/'` אחרי הצלחת login.
- לכן **`'/'` חייב להיות מודע-סשן**: כוקי תקף → הגשת `panel.html` (או הפניה אליה); אין כוקי → הגשת `login.html` (או הפניה אליה). אחרת נוצר לופ התחברות.

מיפוי הקבצים הסטטיים (הצעת מימוש לסוכן השרת): `/style.css` → `public/style.css`, `/login.html` → `public/login.html`, `/panel.html` → `public/panel.html`.

## 5. כללי בטיחות — מחייבים

1. **איסור גמור להחזיר סודות ללקוח.** השרת מחזיר `masked` בלבד (`github_pat_••••`). סוכן הפורטל אסור שיקרא את קבצי `secrets/` ואסור שיזרים ערכי-סוד לשום תשובה, לוג או עמוד. אין "גילוי-סוד לפי-דרישה" — אין endpoint כזה ולא ייבנה.
2. **איסור URL מוחלט בקוד-לקוח.** בדפדפן: `fetch('/api/...')` בלבד + `credentials: 'same-origin'`. כתובת השרת (`:3010`) נטפלת אך ורק מצד-השרת (פרוקסי/משתנה-סביבה).
3. **תשובות פרטיות — אין קאש.** כל תשובה של ה-API (ובפרט `/api/status`) אסורה לשמירה בין-מכשירים/פרוקסים: הוסיפו `Cache-Control: no-store` בפרוקסי הפורטל.
4. **אין סודות בלוג של הלקוח.** יומן הפעולות בממשק מציג תקצירים; גם הפורטל לא יריץ `console.log` על תשובות שעלולות להכיל פרטים רגישים.
5. **טיהור פלט לפני רינדור.** כל שדה דינמי מהתשובות מוזרק כ-`textContent` (כמו בממשק ה-fallback) — לא `innerHTML`. פלט `action` הוא פלט-מערכת ואינו-מהימן לרינדור-HTML.
6. **כל פעולה משפיעה דורשת סשן.** `push-github` וכדומה מבוצעים רק עם כוקי תקף; אין להוסיף ערוצי-הרצה אנונימיים.
7. **429 = המתן.** אחרי `429` ב-login — חובה בק-אוף; לולאת ניסיונות היא באג.

## 6. זרימה מלאה (דוגמת curl, מקומי)

```bash
# 1) כניסה — שומר את הכוקי
curl -s -i -c /tmp/hq.jar -H 'Content-Type: application/json' \
  -d '{"password":"…"}' http://localhost:3010/api/login
# → 200 {"ok":true} + Set-Cookie hq_session (HttpOnly)

# 2) סטטוס
curl -s -b /tmp/hq.jar http://localhost:3010/api/status
# → {"ok":true,"uptime":…,"ports":{…},"git":{…},"vault":[{"name","kind","masked"}],…}

# 3) פעולה
curl -s -b /tmp/hq.jar -H 'Content-Type: application/json' \
  -d '{"action":"git-status"}' http://localhost:3010/api/action
# → {"ok":true,…}

# 4) התנתקות
curl -s -b /tmp/hq.jar -X POST http://localhost:3010/api/logout
# → {"ok":true}; קריאת status נוספת תחזיר 401
```

## 7. הממשק המוכן (public/)

- `public/login.html` — שער הכניסה: עברית-RTL, כהה, אופליין-מלא; `POST /api/login` יחסי; שגיאות עברית (401/429/לא-זמין); הצלחה → `'/'`.
- `public/panel.html` — לוח המפעיל: `GET /api/status` (רענון 30 שניות + `visibilitychange`), `POST /api/action` ×3 עם לוג-גלילה, `POST /api/logout`; `401` בכל קריאה → `'/'`; הכל `textContent` + `credentials:'same-origin'`.
- `public/style.css` — פלטה כהה-ניטרלית, הדגשות ירוק/אדום בלבד (אפס-כחול/indigo), משתני-CSS, כפתורים ≥44px, `:focus-visible`, scrollbar מעוצב.
